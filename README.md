# Automation

파일 정리 자동화 도구 `organize`.

여러 정리 작업(압축 해제 · 중복 제거 · 종류별 분류 · 날짜별 분류)을 골라 순서대로 엮어 실행한다.
자주 쓰는 조합은 이름을 붙여 저장한다.

## 새 PC 에서 시작하기

이 저장소는 **특정 PC 를 전제하지 않는다.** 클론한 뒤 아래 순서면 동작한다.

```
git clone <이 저장소>
cd Automation

python -m organize doctor                     환경 점검. 부족한 것을 알려준다
python -m organize list                       쓸 수 있는 레시피를 보여준다
python -m organize preview desktop            미리보기 (파일을 건드리지 않는다)
python -m organize run desktop --apply        실제 실행
python -m organize undo --root @desktop       방금 실행을 되돌린다
```

`undo` 는 **어느 폴더를 되돌릴지** 알아야 한다. `--root <폴더>` 로 짚어 주거나,
방금 실행한 레시피 이름을 `--recipe <레시피>` 로 준다. 실행이 끝나면 화면 맨 끝에
그대로 복사해 쓸 수 있는 되돌리기 명령이 나온다.

싣고 있는 레시피는 세 개다.

| 레시피 | 대상 폴더 | 하는 일 |
|---|---|---|
| `desktop` | `@desktop` (바탕화면) | 중복 치우기 → 종류별 폴더로 분류 |
| `downloads` | `@downloads` (다운로드) | 중복 치우기 → 종류별 폴더로 분류 |
| `photos` | `@pictures` (사진) | 사진/캡처/영상으로 나눈 뒤 사진은 연도별로 |

`photos` 의 사진·캡처 구분은 EXIF 촬영정보로 한다 — **`Pillow` 가 없으면 그 두 규칙은
아무 파일도 분류하지 못한다.** `organize doctor` 가 그 사실을 알려준다.

필요한 것은 **Python 3.11 이상**뿐이다. 외부 패키지는 없다.

> ⚠️ **윈도우에서는 윈도우 파이썬으로 돌린다.** WSL 안에서 `/mnt/c/...` 를 정리하면
> 훨씬 느리다. 도구가 느린 게 아니라 **WSL 이 윈도우 파일에 접근하는 값**이다 —
> 실측: 파일 125개 미리보기가 WSL 경유로 **61.8초**, 그중 실제 계산은 **8.3초**뿐이었다.
> 나머지 53초는 전부 파일 하나하나를 건너편에서 읽어 오는 시간이다.
> 같은 코드를 윈도우 파이썬(`PS> python -m organize ...`)으로 돌리면 이 값이 사라진다.
(`Pillow` 는 선택이다 — 있으면 사진의 촬영일과 촬영기기를 읽는다. 없으면 날짜는
파일명·수정시각으로 대체하지만, **사진/캡처 구분은 대체가 없다.**)

`config.local.json`(이 PC 의 폴더 위치)은 저장소에 포함되지 않는다.
없어도 동작하며, 백업 드라이브 같은 위치를 추가하고 싶을 때만 지정한다.

## 현재 상태

**쓸 수 있다.** 미리보기 → 실행 → 되돌리기가 전부 동작한다.

| 부분 | 상태 |
|---|---|
| 폴더 훑기 · 날짜 판정 · 중복 판정 | 됨 |
| 분류 규칙(프로파일) 읽기 | 됨 |
| 압축 풀기 · 중복 치우기 · 종류별 분류 · 날짜별 분류 | 됨 |
| 실제 파일 이동 | 됨 |
| 작업들을 엮는 러너 · 실제로 수행하는 실행기 | 됨 |
| 되돌리기(undo) | 됨 |
| CLI · 레시피 | 됨 |
| **윈도우에서 실사용 검증** | **아직** — 아래 참고 |
| GUI | 다음 계획 |

작업은 `feat/organize-engine-cli` 브랜치에서 한다. `main` 은 아직 초기 상태다.

만들어진 부분이 실제로 도는지는 이렇게 확인한다:

```
python3 -m pytest -q
```

### 아직 윈도우에서 확인하지 않은 것

개발은 WSL(리눅스)에서 했다. 아래는 **논증만 했고 실제 윈도우에서 확인하지 않았다.**
"확인했다" 고 말할 수 없는 항목들이다.

| 무엇 | 왜 리눅스에서 확인이 안 되는가 |
|---|---|
| **드라이브를 넘는 이동** (`C:` → `D:`) | 운영체제가 주는 오류 번호가 다를 수 있다. 다르면 **통째로 실패한다** |
| 경로가 정리 대상 폴더 밖으로 나가는 것 막기 | `C:\`, `\\서버\공유` 형태 판정을 리눅스에서 못 돈다 |
| 경로 260자 제한 | 리눅스에 그 제한이 없다 |
| 대소문자 무시 (`A.txt` == `a.txt`) | 리눅스는 다른 파일로 본다 |
| 열려 있는 파일은 이동 불가 | 리눅스는 열려 있어도 옮겨진다 |
| 바로가기(`.lnk`) · junction | 리눅스에 없는 개념이다 |

검증 절차는 [`docs/superpowers/specs/2026-08-24-acceptance-scenarios.md`](docs/superpowers/specs/2026-08-24-acceptance-scenarios.md)
에 시나리오별로 적어 두었다. **진짜 폴더에 `--apply` 하기 전에 복사본에서 먼저 돌린다.**

## 명령어

| 명령 | 하는 일 |
|---|---|
| `doctor` | 환경 점검 — 파이썬 버전, 폴더 위치, 남은 흔적 |
| `paths` | 폴더 위치 확인·지정 (`--set archive=D:/보관`) |
| `list` | 레시피와 분류 설정 목록 |
| `preview <레시피>` | 미리보기. **파일을 건드리지 않는다** |
| `run <레시피> --apply` | 실제 실행 |
| `undo` | 방금 실행을 되돌린다 |
| `do <작업>` | 레시피 없이 작업 하나만 실행 |

`--apply` 를 붙이지 않으면 **어떤 파일도 생성·이동·삭제하지 않는다.**
치우는 것은 전부 격리 폴더(`.organize/trash/`)로 옮기는 것이며, 지우지 않는다.

### 정리는 **한 폴더 안에서만** 일어난다

이 도구는 **정리 대상 폴더(`--root`) 밖으로 파일을 내보내지 않는다.** 분류 폴더도
격리 폴더도 전부 그 안에 만든다. 실수로 엉뚱한 곳을 건드리지 않기 위한 설계다.

```
$ organize do route --dest /다른곳/백업 --root ~/작업
  실패: 'route' 작업의 목적지가 정리 대상 폴더 밖을 가리킵니다
```

그래서 **`C:` 의 파일을 `D:` 로 보내는 정리는 할 수 없다.** 옛 `legacy/result.py` 는
`F:\day` 로 옮겼지만 이 도구는 그렇게 하지 않는다. 다른 드라이브로 옮기려면
그 드라이브를 `--root` 로 잡아 따로 정리하거나, 옮기는 것 자체는 탐색기로 한다.
