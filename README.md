# organize

파일 정리 자동화 도구.

여러 정리 작업(압축 해제 · 빈 파일 치우기 · 중복 제거 · 종류별 분류 · 날짜별 분류)을
골라 순서대로 엮어 실행한다. 자주 쓰는 조합은 이름을 붙여 저장한다.

![체크박스로 할 일을 고르고, 미리보기에서 보류(중복 파일)를 무리로 묶어 보여준다](docs/images/메인화면_보류.png)

**처음 설치해 본다면** → [설치.md](설치.md) 를 먼저 본다. 이 문서는 이미 git·파이썬을
다룰 줄 아는 사람 기준으로 짧게 쓴 버전이다.

## 시작하기

이 저장소는 **특정 PC 나 특정 사람을 전제하지 않는다.** 클론한 뒤 아래 순서면 동작한다.

```
git clone https://github.com/daxjective/organize.git
cd organize

python -m organize doctor                     환경 점검. 부족한 것을 알려준다
python -m organize gui                        창으로 쓴다 (이쪽을 권한다)
```

명령줄로 쓰려면:

```
python -m organize list                       쓸 수 있는 레시피를 보여준다
python -m organize preview desktop            미리보기 (파일을 건드리지 않는다)
python -m organize run desktop --apply        실제 실행
python -m organize undo --root @desktop       방금 실행을 되돌린다
```

`undo` 는 **어느 폴더를 되돌릴지** 알아야 한다. `--root <폴더>` 로 짚어 주거나,
방금 실행한 레시피 이름을 `--recipe <레시피>` 로 준다. 실행이 끝나면 화면 맨 끝에
그대로 복사해 쓸 수 있는 되돌리기 명령이 나온다.

싣고 있는 레시피는 세 개다.

| 레시피 | 대상 폴더 | 하는 일 |
|---|---|---|
| `desktop` | `@desktop` (바탕화면) | 중복 치우기 → 종류별 폴더로 분류 |
| `downloads` | `@downloads` (다운로드) | 중복 치우기 → 종류별 폴더로 분류 |
| `photos` | `@pictures` (사진) | `02_Media` 안을 사진/캡처/영상으로 나눈 뒤 사진은 연도별로 |

`photos` 의 사진·캡처 구분은 EXIF 촬영정보로 한다 — **`Pillow` 가 없으면 그 두 규칙은
아무 파일도 분류하지 못한다.** `organize doctor` 가 그 사실을 알려준다. **설치 직후 한
번은 꼭 `organize doctor` 로 "Pillow 있음" 인지 확인한다** — 없으면 `pip install Pillow`
(`python -m pip install Pillow` 로 하면 지금 이 `python` 이 쓰는 곳에 확실히 깔린다).
없어도 창은 뜨고 미리보기도 되므로 **눈치채기 어렵다** — 사진·캡처 분리와 연도별 분류가
그냥 아무 일도 안 하는 것처럼 보일 뿐이다.

필요한 것은 **Python 3.11 이상**뿐이다. 외부 패키지는 없다.

> ⚠️ **윈도우에서는 윈도우 파이썬으로 돌린다.** WSL 안에서 `/mnt/c/...` 를 정리하면
> 훨씬 느리다. 도구가 느린 게 아니라 **WSL 이 윈도우 파일에 접근하는 값**이다 —
> 실측: 파일 125개 미리보기가 WSL 경유로 **61.8초**, 그중 실제 계산은 **8.3초**뿐이었다.
> 나머지 53초는 전부 파일 하나하나를 건너편에서 읽어 오는 시간이다.
> 같은 코드를 윈도우 파이썬(`PS> python -m organize ...`)으로 돌리면 이 값이 사라진다.
(`Pillow` 는 선택이다 — 있으면 사진의 촬영일과 촬영기기를 읽는다. 없으면 날짜는
파일명·수정시각으로 대체하지만, **사진/캡처 구분은 대체가 없다.**)

`config.local.json`(이 PC 의 폴더 위치)은 저장소에 포함되지 않는다.
없어도 동작하며, 백업 드라이브 같은 위치를 추가하고 싶을 때만 지정한다.

### 윈도우에서 확인한 것 / 아직인 것

개발은 WSL(리눅스)에서 했다. 윈도우 파이썬으로 **직접 돌려 확인한 것**은 이만큼이다.

| 무엇 | 결과 |
|---|---|
| `organize doctor` · `organize gui` 가 뜨는가 | 됨 (Python 3.14 · tkinter 8.6) |
| 폴더 위치 자동 인식 | 됨 (바탕화면 · 다운로드 · 문서 · 사진 …) |
| 미리보기 | 됨 |
| 한글 출력을 **파일로 받기** (`> 로그.txt`) | 됨 — 예전에는 `UnicodeEncodeError` 로 죽었다 |

아래는 **논증만 했고 실제 윈도우에서 확인하지 않았다.** "확인했다" 고 말할 수
없는 항목들이다. **`--apply`(실제 파일 이동)가 여기 들어간다.**

| 무엇 | 왜 리눅스에서 확인이 안 되는가 |
|---|---|
| **실제 파일 이동(`--apply`)** | 아래 항목들이 전부 여기서 한꺼번에 걸린다 |
| **드라이브를 넘는 이동** (`C:` → `D:`) | 운영체제가 주는 오류 번호가 다를 수 있다. 다르면 **통째로 실패한다** |
| 경로가 정리 대상 폴더 밖으로 나가는 것 막기 | `C:\`, `\\서버\공유` 형태 판정을 리눅스에서 못 돈다 |
| 경로 260자 제한 | 리눅스에 그 제한이 없다 |
| 대소문자 무시 (`A.txt` == `a.txt`) | 리눅스는 다른 파일로 본다 |
| 열려 있는 파일은 이동 불가 | 리눅스는 열려 있어도 옮겨진다 |
| 바로가기(`.lnk`) · junction | 리눅스에 없는 개념이다 |

검증 절차는 [`docs/superpowers/specs/2026-08-24-acceptance-scenarios.md`](docs/superpowers/specs/2026-08-24-acceptance-scenarios.md)
에 시나리오별로 적어 두었다. **진짜 폴더에 `--apply` 하기 전에 복사본에서 먼저 돌린다.**

## 명령어

| 명령 | 하는 일 |
|---|---|
| `doctor` | 환경 점검 — 파이썬 버전, 폴더 위치, 남은 흔적 |
| `paths` | 폴더 위치 확인·지정 (`--set archive=D:/보관`) |
| `list` | 레시피와 분류 설정 목록 |
| `preview <레시피>` | 미리보기. **파일을 건드리지 않는다** |
| `run <레시피> --apply` | 실제 실행 |
| `undo` | 방금 실행을 되돌린다 |
| `do <작업>` | 레시피 없이 작업 하나만 실행 |
| `gui` | 창으로 쓴다 — 폴더를 탐색기에서 고른다 |

`--apply` 를 붙이지 않으면 **어떤 파일도 생성·이동·삭제하지 않는다.**
치우는 것(`보류`)은 전부 `.organize/trash/` 로 **옮기는** 것이며, 지우지 않는다.
`undo` 로 제자리에 되살릴 수 있다.

### 보류 파일 다루기

내용이 완전히 같은 파일(크기 · 전체 해시까지 비교)은 하나만 남고 나머지가 보류된다.
GUI 미리보기의 「보류」 탭은 같은 무리끼리 묶어서, **남기는 파일**의 자리 · 수정일 ·
크기를 무리 머리에 한 번만 보여준다. 파일 이름을 누르면 탐색기가 그 파일을 **선택한
채로** 뜬다 — 열거나 실행하지 않는다(다운로드 폴더의 중복 설치 파일을 확인하려다
실행되는 사고를 막기 위해서다).

실행을 마친 뒤에는 결과 창에서 **그 실행이 보류시킨 파일만** 지울 수 있다
(`.organize/trash/` 폴더 전체가 아니라 그 실행의 기록에 적힌 것만 — 같은 초에 실행한
다른 작업의 보류 파일까지 지우지 않는다). 지운 뒤에도 **옮긴 파일은 여전히
되돌릴 수 있다**. 이 지우기는 되돌릴 수 없고, CLI 명령은 없다 — GUI 전용이다.

**정리 대상 폴더 안에 코드 프로젝트(설치 폴더, `node_modules`, 파이썬 배포판 등)가
있으면 주의한다.** 그런 폴더 안에는 내용이 완전히 빈(0바이트) 부속 파일이 흔하다
(`REQUESTED`, `py.typed`, 빈 `__init__.py` 등). "내용이 완전히 같은 파일" 판정은 이런
빈 파일끼리도 걸리므로, 정리 대상 폴더 바로 밑에 있는 사용자의 0바이트 파일이 그
프로젝트 폴더 안의 부속 파일과 "같은 내용"으로 묶여 보류될 수 있다 — 하위 폴더에 있는
쪽이 항상 "원본"으로 뽑히기 때문이다. **「빈 파일 치우기」를 먼저 켜 두면** 이런 파일이
따로 걸러져 이런 혼동이 없다.

### 사진이 예상과 다르게 갈릴 때

- **사진·캡처 분리, 연도별 분류가 통째로 아무 일도 안 한다** → 거의 항상 `Pillow` 가
  없는 경우다. `organize doctor` 로 확인한다(위 참고). 창은 멀쩡히 뜨고 미리보기도
  되므로 실행해 보기 전에는 알아채기 어렵다.
- **파일 이름의 날짜(연도)를 손으로 바꿔도 그 연도 폴더로 안 간다** → 의도된 동작이다.
  연도 판정은 **①EXIF 촬영일 → ②파일명 날짜 → ③수정시각** 순서로, 사진 안에 EXIF
  촬영일이 남아 있으면 파일명이 뭐라고 되어 있든 그쪽을 따른다(`organize/core/dates.py`).
  파일명은 옮기다 흐트러질 수 있지만 EXIF 는 찍은 순간 그대로라 더 정확하기 때문이다.
  실제 촬영일을 보려면 탐색기에서 그 사진의 속성 → 자세히 탭의 "찍은 날짜"를 본다.

### 정리가 일어나는 범위

기본은 **정리 대상 폴더(`--root`) 안**이다. 분류 폴더도 보류 폴더도 전부 그 안에
만든다. **손으로 쓴 경로로는 밖에 나갈 수 없다** — 오타 하나로 파일이 엉뚱한 곳에
흩어지는 것을 막기 위해서다.

```
$ organize do route --profile desktop --dest /다른곳/백업 --root ~/작업
  실패: 'route' 작업의 목적지가 정리 대상 폴더 밖을 가리킵니다: /다른곳/백업/01_Docs
```

**밖으로 내보내려면 그 위치를 먼저 이름으로 등록한다.** 등록이라는 한 단계가
안전장치다 — 오타는 등록되어 있지 않다.

```
$ organize paths --set 백업=D:/보관          이름을 등록한다
$ organize paths --pick 백업                 (또는 탐색기에서 고른다)

$ organize do route --profile desktop --dest @백업 --root ~/작업
  ⚠ 이 정리는 파일을 정리 대상 폴더 밖으로 내보냅니다.
      보낼 곳: D:/보관   (1개)
      되돌리기 전까지 이 파일들은 원래 폴더에 없습니다.
```

그래서 **`C:` 의 파일을 `D:` 로 보내는 정리는 할 수 있다.** 드라이브를 넘을 때는
옮기기(`os.replace`)가 안 되므로 복사한 뒤 원본을 지운다 — 크기를 확인하고 나서만
지운다. 다만 **이 경로는 아직 윈도우에서 확인하지 않았다**(위 표 참고).

창(`organize gui`)에서는 밖으로 내보내는 항목을 두지 않았다. 화면의 [할 일] 체크박스는
전부 대상 폴더 안에서만 움직인다 — 밖으로 보내려면 레시피 파일의 `dest` 에
`@이름` 을 적는다.

### 폴더 자체는 옮기지 않는다

이 도구가 옮기는 것은 **파일뿐이다.** 폴더는 만들기만 한다(분류 결과를 담을
`01_Docs` 같은 것). `~/작업/사진모음/` 이라는 폴더를 통째로 다른 곳으로 옮기는
일은 **못 한다** — 훑는 단계에서 폴더를 아예 목록에 넣지 않기 때문이다
(`organize/core/scanner.py`). 폴더를 통째로 옮기는 것은 탐색기로 한다.
