**출처** — `docs/prototype/organize-prototype.html` 의 "화면 시안" 절.
커밋 `604b5a9` "organize 화면 시안, ui_1.html 참고해 **Finder 톤**으로 재단장".
그 HTML 은 102KB 라 매번 읽기 비싸다. **여기가 실행용 발췌본이다.**

**방향** — 사용자가 **A** 를 골랐다(2026-08-25): 시안 그대로. 작업을 체크박스로
켜고 끄고 순서를 바꿔 **레시피를 화면에서 조립**한다.

## 왜 이렇게 그렸나 — 설계의 핵심 문장 셋

1. **"대상은 경로 입력창이 아니라 이름 드롭다운. 경로를 칠 일이 없다."**
   → 메인 화면에 경로 입력창도 [찾아보기] 버튼도 **없다.** 탐색기는 설정 화면에서
   위치를 등록할 때만 쓴다. (WSL 에서 tkinter 탐색기는 리눅스 파일시스템만
   보여주므로, 메인에서 탐색기를 안 쓰는 이 설계가 이식성에도 유리하다.)

2. **"경로가 아니라 파일 개수를 보여주는 게 핵심."**
   → 첫 화면이 폴더마다 **파일 개수**를 보여준다. OneDrive 백업이 켜진 PC 에서는
   진짜 바탕화면이 다른 곳이라 여기가 "바탕화면 **0**" 으로 뜬다.
   경로 문자열만 보여주면 일반 사용자는 틀린 것을 못 알아챈다.

3. **"PC 를 옮기면 없는 경로만 빨갛게 뜬다. 그것만 다시 지정하면 끝."**
   → 설정 화면은 정상인 것을 조용히 두고 **문제만 눈에 띄게** 한다.

## 화면 1 — 처음 실행

```
┌─ organize — 처음 실행 ─────────────────────┐
│  폴더 위치를 자동으로 찾았습니다.            │
│                                            │
│    바탕화면    …\Desktop        6          │
│    다운로드    …\Downloads    121          │
│    문서        …\Documents     19          │
│    사진        …\Pictures       2          │
│                                            │
│  이 위치가 맞나요?                          │
│         [ 맞아요, 시작 ]  [ 직접 고를게요 ] │
└────────────────────────────────────────────┘
```

- 경로는 `…\Desktop` 처럼 **꼬리만** 보여주고, **개수를 크게** 보여준다.
- 개수가 `0` 인 줄은 눈에 띄게 — OneDrive 리디렉션 신호다.
- [직접 고를게요] → 설정 화면(화면 3).
- 설정이 이미 있으면 이 화면을 건너뛴다.

- **레시피 드롭다운** — 저장해 둔 조합을 고른다. [저장] 이 지금 조합을 레시피로 저장.
- **대상 드롭다운** — 등록된 **이름**(다운로드·바탕화면·백업드라이브…). 경로를 안 친다.
- **작업 체크박스** — 켠 것만, **보이는 순서대로** 실행된다. ▲▼ 로 순서를 바꾼다.
  오른쪽 회색 글씨는 그 작업의 현재 설정 요약(대상 폴더 등).
- **결과 탭** — `이동 117` · `격리 2` 처럼 종류별로 나눠 센다.
  **폴더 생성은 파일 개수에 섞지 않는다**(이 프로젝트가 이미 겪은 실수).
- **파일별 체크박스** — 끄면 그 파일만 이번 실행에서 뺀다("제외함").

```
│    사진보관        없음 · 다시 지정  ← 빨강  │
│                                            │
│  폴더 이름                                  │
│    문서            01_Docs                  │

│                                            │

└────────────────────────────────────────────┘
```

- 자동으로 찾은 위치는 **정상이면 조용히** 둔다.
- 내가 추가한 위치에 [찾아보기] 를 둔다 — **탐색기를 쓰는 유일한 자리**.
- 없는 경로만 빨갛게 + "다시 지정".
- 폴더 이름은 `config.local.json` 의 `folder_names` 자리 — **아직 엔진이 안 읽는다.**
  화면을 먼저 만들면 "바꿨는데 안 바뀐다" 가 된다. 엔진이 읽게 하거나 화면에서 뺀다.

## A 방향이 엔진에 요구하는 것

| 필요한 것 | 지금 되나 | 비고 |
|---|---|---|
| 작업 목록을 화면에 뿌리기 | ❌ | 블록별 **사람이 읽을 이름**과 기본 설정 목록이 필요 |
| 켠 것만 순서대로 실행 | ✅ | `build_plan(root, steps, ...)` 이 steps 를 그대로 받는다 |
| 조합을 레시피로 저장 | ✅ | `recipes.save_recipe` 가 이미 있다 |
| **파일별로 빼기** | ❌ | **이번 계획의 유일한 진짜 신규 기능** |
| 대상 이름 드롭다운 | ✅ | `paths` 가 이미 이름→경로를 안다 |
| 첫 화면 파일 개수 | ✅ | `doctor` 가 이미 세고 있다 |

### 파일별로 빼기 — 조심할 곳

미리보기 뒤 사용자가 체크를 끄면 그 파일만 빼고 실행한다. 계획에서 동작 하나를
빼는 일이라 **다음을 깨뜨릴 수 있다.**

1. **빈 폴더** — 그 폴더로 가는 파일을 다 뺐는데 `mkdir` 이 남으면 빈 폴더가 생긴다.
2. **이름 밀림** — `보고서_(1).pdf` 는 앞 파일이 `보고서.pdf` 를 차지했기 때문이다.
   앞 것을 빼면 뒤 것은 `_(1)` 일 이유가 없어진다.
3. **사슬** — 한 파일이 여러 번 옮겨지는 계획에서 중간을 빼면 뒤가 어긋난다.

**가장 안전한 방법: 뺀 목록을 반영해 계획을 다시 세운다.** 동작을 골라내지 말고,
`build_plan` 을 `exclude=<뺀 파일들>` 로 다시 부른다. 그러면 이름도 폴더도 전부
다시 계산되어 **미리보기와 실행이 계속 같다.** 이 도구의 존재 이유가 그것이다.

## 이미 만들어 둔 것 (재사용)

- `organize/gui_model.py` — `Session`. 창 없이 테스트되는 로직.
  **버튼 켜짐/꺼짐 규칙, 미리보기 무효화, 밖으로 나감 표시**가 여기 있다.
  A 방향에서도 이 뼈대는 그대로 쓴다(작업 조립·파일별 빼기를 얹는다).
- `organize/picker.py` — 탐색기 창. 설정 화면에서만 쓴다.
- `organize/gui.py` — **시안과 다르게 만든 창. 다시 쓴다.**
  ("무엇을 어떻게" 영역, 경로 입력창 + 찾아보기는 시안에 없다.)

## 반드시 기억할 제약

- **WSL 에서 tkinter 탐색기는 리눅스 파일시스템만 보여준다.** `E:\` 같은 드라이브
  문자가 안 보인다. **GUI 는 윈도우 파이썬으로 돌려야 한다.** 속도 때문에도 그렇다
  (WSL 경유 실측: 파일 125개 미리보기 61.8초 중 실제 계산은 8.3초).
- `tkinter` 는 **없을 수 있다.** 없으면 GUI 만 못 쓰고 CLI 는 그대로 돌아야 한다.
- 미리보기가 기본. `--apply` 없이 파일을 건드리지 않는다.
- 되돌릴 수 없게 되는 것이 최악의 실패다.
