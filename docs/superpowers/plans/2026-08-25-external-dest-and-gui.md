# 계획 — 다른 드라이브로 백업 + 폴더 고르는 창

**왜 하나** — 이 도구를 만든 이유가 **데이터 백업과 관리**다. SD카드·USB로 옮기는 것이
포함되고, 그건 시작할 때부터 있던 요구다. 지금은 정리 대상 폴더 안에서만 움직일 수 있어서
**백업 자체가 안 된다.** 옛 `legacy/result.py` 는 `F:\day` 로 옮겼다 — 되던 것이 없어졌다.

**GUI 를 원한 진짜 이유** — 화면이 예뻐서가 아니라 **파일 탐색기로 위치를 고르기 위해서**다.
드라이브 문자를 외워 타이핑하거나 JSON 을 손으로 여는 대신, 꽂고 골라 클릭한다.

**둘은 한 덩어리다.** 탐색기로 고른 위치만 목적지로 허용하면, 오타로 파일이 흩어지는 사고가
원천적으로 없어진다. 고르는 행위가 곧 안전장치다.

---

## Global Constraints

- **Python 3.11 이상. 필수 외부 의존성 0.** `tkinter` 는 표준 라이브러리다(윈도우 파이썬 기본 포함).
  없는 환경에서는 GUI 만 못 쓰고 **CLI 는 그대로 돌아야 한다.**
- **미리보기가 기본.** `--apply` 없으면 어떤 파일도 생성·이동·삭제하지 않는다.
- **파일을 삭제하지 않는다.** 치우는 것은 전부 격리 폴더로 이동이다.
- **무엇을 했든 되돌릴 수 있다.** 되돌릴 수 없게 되는 것이 최악의 실패다.
- **손으로 쓴 경로로는 밖으로 못 나간다.** 등록된 이름(`@별칭`)으로만 나간다.
- **오류 메시지는 한국어로.** 파이썬 예외를 그대로 노출하지 않는다. `hint` 를 같이 준다.
- **조용한 무작동 금지.** 이 프로젝트를 여덟 번 문 병이다.
- 테스트는 `tmp_path` 만 쓴다. 커밋 메시지는 한국어.

## 1단계 — 다른 드라이브로 보내기 (백엔드)

### Task 1: `@별칭` 목적지를 Context 가 알게 한다

**Files:** `organize/core/context.py`, `organize/core/runner.py`, `tests/test_context.py`

- `Context.__init__` 에 `external: dict[str, Path] | None = None` 추가.
  이름 → 실제 경로. **러너가 설정에서 풀어서 넣어 준다.**
- `Context.external_path(name) -> Path | None`
- 러너는 레시피의 `dest` 중 `@` 로 시작하는 것만 골라 `resolve_alias` 로 풀어 넘긴다.
  **등록되지 않은 이름이면 그 자리에서 한국어로 거부한다**(파일을 건드리기 전에).

### Task 2: `dest_folder` 가 등록된 밖을 허용한다

**Files:** `organize/blocks/__init__.py`, `tests/test_blocks_common.py`

```
rel 이 "@" 로 시작 → Context 에 등록된 경로면 그 아래로. 아니면 거부.
그 밖의 모든 값 → 지금 그대로 root 안쪽만 허용.
```

- `..`, 절대경로, `~` 는 **계속 거부**한다. 완화하지 않는다.
- 거부 메시지는 등록하는 법을 알려준다: `organize paths --set 백업=E:/정리`

### Task 3: 실행기가 등록된 밖을 허용한다

**Files:** `organize/core/executor.py`, `tests/test_executor.py`

- `_guard_within_root` 를 `_guard_destination` 으로: root **또는** 등록된 외부 경로 아래면 통과.
  심볼릭 링크를 푼 실제 경로로 판정하는 것은 그대로.
- `BuiltPlan` 에 허용된 외부 경로 목록을 실어 나른다.

### Task 4: 드라이브가 없으면 파일을 건드리기 전에 멈춘다

**Files:** `organize/core/runner.py` 또는 `organize/cli.py`, `tests/test_cli.py`

- SD카드·USB 는 **안 꽂혀 있을 수 있다.** 계획을 세운 뒤 실행 직전에 목적지 드라이브가
  실제로 있는지 확인하고, 없으면 **한 파일도 옮기지 않은 채** 한국어로 알린다.
- 별칭에 경로를 여러 개 적으면 있는 것을 고른다(`_first_existing` 이 이미 한다).

### Task 5: 미리보기가 "밖으로 나간다" 를 눈에 띄게 알린다

**Files:** `organize/cli.py`, `tests/test_cli.py`

- 목적지가 정리 대상 폴더 밖이면 총계 위에 한 줄:
  `⚠ 이 정리는 파일을 다른 위치로 내보냅니다: E:\정리 (12개)`
- `--verbose` 에서도 그 항목이 밖으로 가는 것이 보여야 한다.

### Task 6: 목적지에 이미 있는 이름을 미리보기가 본다

**Files:** `organize/core/context.py`, `tests/test_context.py`

- `claim_name` 은 지금 `files_at(rel)` 로 **정리 대상 폴더 안**만 본다. 외부 목적지는
  비어 있는 것으로 보여 미리보기가 이름 충돌을 못 알린다.
- 외부 목적지는 그 폴더를 실제로 한 번 훑어 이름을 채운다(폴더당 한 번).
- 실행 시 `claim_path` 가 원자적으로 다시 잡으므로 **덮어쓰기 위험은 없다.**
  이건 미리보기의 정직함 문제다.

### Task 7: 드라이브를 넘는 되돌리기

**Files:** `tests/test_undo.py`, 필요하면 `organize/core/undo.py`

- 실행 기록에 **절대경로**가 남으므로 원리상 된다. **실측으로 확인한다.**
- 서로 다른 파일시스템 사이(`EXDEV`)에서 왕복이 되는지 테스트로 못박는다
  (리눅스에서 `tmpfs` ↔ `ext4` 로 확인 가능 — `errno=18` 실측 완료).
- 되돌릴 때 드라이브가 없으면 **기록을 잃지 않고** 한국어로 알린다(재시도 가능해야 한다).

## 2단계 — 폴더 고르는 창 (GUI)

### Task 8: `organize paths --pick <이름>`

**Files:** `organize/cli.py`, `organize/picker.py`(신규), `tests/test_picker.py`

- `tkinter.filedialog.askdirectory()` 로 폴더를 고르게 하고 `config.local.json` 에 저장.
- **`tkinter` 가 없으면 죽지 않는다.** 한국어로 "이 파이썬에는 창을 띄울 수 없습니다"
  라고 알리고 `--set` 으로 직접 적는 법을 안내한다.
- 창을 띄우는 부분과 저장하는 부분을 **분리**한다 — 저장 로직은 창 없이 테스트한다.

### Task 9: `organize gui` — 창 하나

**Files:** `organize/gui.py`(신규), `organize/cli.py`, `tests/test_gui_logic.py`

화면에 있어야 하는 것(최소):

| 요소 | 하는 일 |
|---|---|
| 정리할 폴더 | **[찾아보기]** 버튼 → 탐색기 |
| 레시피 | 목록에서 고르기 |
| 보낼 곳(선택) | **[찾아보기]** → 등록 후 목적지로 |
| [미리보기] | 결과를 표에 표시. **파일 안 건드림** |
| [실행] | 미리보기를 본 뒤에만 켜진다 |
| [되돌리기] | 마지막 실행 되돌리기 |

- **로직과 위젯을 분리한다.** 무엇을 보여줄지 계산하는 부분은 창 없이 테스트한다.
  위젯은 그 결과를 그리기만 한다.
- `tkinter` 가 없으면 `organize gui` 가 한국어로 안내하고 종료(코드 1).

### Task 10: 실제로 띄워 보고 화면을 확인한다

- WSLg 로 창을 띄워 캡처한다. **눈으로 확인하지 않은 화면은 됐다고 하지 않는다.**
- 폴더 고르기 → 미리보기 → 실행 → 되돌리기 왕복을 창에서 직접 해 본다.

## 하지 않는 것

- 네트워크 드라이브(`\\서버\공유`) 전용 처리 — 경로로 잡히면 그냥 되고, 따로 다루지 않는다.
- 여러 목적지로 동시에 보내기 — 한 레시피는 한 곳으로.
- GUI 에서 레시피를 만들거나 편집하는 것 — 다음 계획.
