동작 원리

기존 스크립트는 폴더를 돌면서 곧바로 파일을 옮겼습니다. 그래서 미리보기가 원리적으로 불가능했고 되돌릴 수도 없었습니다. 새 구조는 “무엇을 할지 정하는 일”과 “실제로 하는 일”을 분리합니다.

미리보기와 실행이 같은 목록을 씁니다. “돌려봤더니 예상과 달랐다”가 구조적으로 생길 수 없습니다.

직접 돌려보기

왼쪽에서 폴더와 작업을 고르고 미리보기를 누르면, 실제 파일 목록에 규칙을 적용한 결과가 나옵니다. 작업을 켜고 끄거나 ▲▼로 순서를 바꾸면 다음 작업의 대상이 따라 바뀝니다 — 이게 체인 구조의 핵심입니다. 결과 목록의 체크를 풀면 그 파일만 빼고 실행됩니다.

실제 파일이 알려준 것

설계를 세우고 나서 이 PC의 진짜 파일에 돌려봤습니다. 두 가지가 확인됐고, 그중 하나는 기존 방식의 결함이었습니다.

스크린샷은 이름을 안 봐도 갈린다

카메라·휴대폰 사진에는 EXIF에 제조사와 기종이 반드시 들어갑니다. 화면 캡처에는 절대 없습니다.

다운로드 폴더의 유튜브 캡처 105장은 이름이 사피엔스 스튜디오 - … [영상ID - 1248x702 - 1h00m38s].png 형태라 “screenshot”이라는 단어가 하나도 없습니다. 이름 규칙으로는 못 잡고, EXIF로는 전부 잡힙니다.

이름으로 중복을 찾으면 틀린다

PicPick 폴더 150장에 내용 해시를 돌렸더니 중복 23쌍이 나왔는데, 이름이 서로 완전히 다른 파일들이었습니다. 같은 화면을 다른 날 다시 캡처한 것입니다.

남김내용이 같아 격리

2026-06-05 09 59 21 (2).png2026-06-06 00 33 59 (2).png
2026-06-05 09 59 21 (3).png2026-06-06 00 33 59 (3).png
기존 메모의 “끝에 숫자 달린 중복 파일명을 제거” 방식이었다면 진짜 중복 23쌍은 하나도 못 찾고, 서로 다른 이미지인 (2), (3) 파일들을 지웠을 것입니다.

건드리면 안 되는 파일이 있다

세 폴더를 전부 돌려보니 desktop.ini 가 99_Unsorted 로 분류되고 있었습니다. Windows 가 폴더 아이콘과 이름을 저장하는 시스템 파일이라, 옮기면 그 폴더의 설정이 깨집니다. 실제 파일에 돌려보지 않았으면 못 잡았을 문제입니다.

제외 목록을 규칙보다 먼저 적용합니다. desktop.ini, Thumbs.db, .DS_Store, Office 임시 파일~$… 은 어떤 프로파일을 써도 손대지 않습니다. 시뮬레이터의 “손대지 않음” 탭에서 확인할 수 있습니다.

어디까지 되나

작업 하나만 켜면 예전에 만드신 단일 스크립트와 같습니다. 엮으면 앞 작업이 만든 폴더가 다음 작업의 대상이 됩니다.

하나만 쓰기

바탕화면에서 md 파일만 골라 문서/메모 아래 연도별로. 나머지는 손대지 않음.

{ "root": "@desktop",
  "steps": [
    { "block": "by_date",
      "when": { "ext": [".md"] },
      "dest": "@documents/메모",
      "layout": "{year}" }
  ] }

2026-07-12 회의록.md
  → 문서/메모/2026/

엮어 쓰기

종류별로 가른 뒤 사진 폴더만 다시 캡처·사진으로, 사진만 다시 연도별로.

steps:
  route    →  01_Docs · 02_Media …
  route    02_Media  캡처 / 사진
  by_date  02_Media/사진  {year}

@pictures 실제 결과
  02_Media/캡처/       1
  02_Media/사진/2026/  1
  (desktop.ini 는 제외)

PC가 바뀌어도

별칭에 대체 경로를 주면 외장하드가 없어도 레시피가 죽지 않습니다.

"archive": [
   "F:/day",
   "D:/보관",
   "@documents/Archive"
]

외장하드 꽂음  → F:/day
안 꽂음        → 문서/Archive
둘 다 없음     → 만든다

시뮬레이터는 C:\Users\cloocus 의 Downloads · Documents\PicPick · Pictures 를 2026-08-20 에 읽은 실제 목록으로 동작합니다. 규칙 적용은 진짜지만 파일을 옮기지는 않습니다.
