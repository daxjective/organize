3. 빠진 핵심 — 다른 드라이브로 보내기

지금은 정리 대상 폴더 밖으로 파일을 못 내보낸다.

$ organize do route --dest E:\백업 --root C:\Users\...\Downloads
  실패: 'route' 작업의 목적지가 정리 대상 폴더 밖을 가리킵니다

옛 legacy/result.py 는 F:\day 로 옮겼다. 예전엔 되던 것이 지금은 없다.

왜 막아 뒀나

오타 하나(.., 절대경로)로 파일이 엉뚱한 곳에 흩어지는 것을 막기 위해서다. 그 걱정 자체는 옳다. 문제는 “막는 것”과 “못 하게 하는 것”을 구분하지 않은 것이다.

제안하는 구조 — 이름을 붙인 곳으로만 내보낸다

손으로 쓴 경로
--dest E:\백업 → 계속 거부
먼저 이름을 붙이고
paths --set 백업=E:\정리 → 그 이름으로만
--dest @백업 → 허용

한 번 등록하는 수고가 오타 사고를 막는 장치가 된다. 등록된 곳은 config.local.json 에 남아 손으로 열어 고칠 수 있다.

같이 처리해야 하는 것들

상황어떻게
SD카드·USB가 안 꽂혀 있음실행 전에 멈춘다 — 파일이 한 개도 안 움직인 상태로
옮기는 도중 빠짐복사 → 크기 확인 → 삭제 순서라 원본이 살아남는다
드라이브가 다름복사 후 검증. 이미 만들어져 있다(EXDEV 처리)
되돌리기실행 기록에 절대경로가 남으므로 드라이브를 넘어도 되돌아온다
미리보기 화면“다른 드라이브로 나갑니다” 를 눈에 띄게 표시

4. 경로 — 기억하되 언제든 고칠 수 있게

무엇어디에고치는 법
내가 등록한 위치config.local.jsonorganize paths --set 백업=E:\정리 또는 파일을 직접 편집
최근 정리한 폴더.organize/recent-roots.json자동 기억(최근 20개). 지워도 됨
옛 스크립트 경로legacy/*.py 맨 위표시된 한 줄만 바꾸면 됨

config.local.json 은 저장소에 올라가지 않는다. PC 를 옮기면 새로 등록하면 되고, 없어도 도구는 그냥 돈다.

// config.local.json — 손으로 열어 고쳐도 된다
{
  "paths": {
    "백업":   "E:/정리",
    "사진보관": ["E:/사진", "D:/사진"]     // 위에서부터 실제로 있는 것을 쓴다
  }
}

목록으로 적으면 외장하드를 안 꽂아도 레시피가 죽지 않는다 — 있는 것을 골라 쓴다.
