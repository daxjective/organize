# 확인 체크리스트 — 보류 무리보기 (2026-08-28)

이번 작업은 서브에이전트 8개가 나눠서 짰고, 컨트롤러(저)가 중간중간 검토했다.
사용자가 직접 확인·승인한 지점은 **브레인스토밍 단계의 질문 5개**와 **스펙 승인**
뿐이었고, 이후 구현·리뷰·병합은 전부 자동으로 돌았다. 그래서 사용자가 직접
눈으로 본 적 없는 지점들을 여기 모은다.

## 1. 지금 바로 눈으로 확인하면 좋은 것

### ① 실제 윈도우 파이썬에서 [보류한 N개 지우기] — 아직 검증 안 됨

이번 계획에서 **가장 위험한 코드**(파일을 진짜로 지우는 유일한 곳)인데,
지금까지의 확인은 전부 **WSL 안 tkinter + 가짜 샌드박스 폴더**에서였다.
실제 윈도우 파이썬(`PS> python -m organize gui`)으로는 한 번도 안 돌려봤다.

**해볼 것**: 아무 폴더에 테스트용 중복 파일 몇 개 만들어서(`보고서.pdf` 복사본
여러 개) → 미리보기 → 실행 → 결과 창의 [보류한 N개 지우기] → 확인 → 정말
`.organize/trash/` 안이 비는지, [되돌리기]가 그 뒤에도 되는지.

### ② 탐색기 "선택해서 열기" — 실행 경로가 WSL 과 다르다

`picker.py` 의 `reveal_file` 은 WSL 이냐 아니냐에 따라 **다른 코드 줄**을 탄다.

| | WSL (내가 확인함) | 진짜 윈도우 파이썬 (안 해봄) |
|---|---|---|
| 부르는 프로그램 | `explorer.exe` | `explorer` |
| 경로 변환 | `wslpath -w` 거침 | 그냥 `str(path)` |

같은 목적의 코드지만 **실제로 도는 줄은 다르다.** 보류 탭에서 파일 이름을
눌러 탐색기가 그 파일을 선택한 채 뜨는지 직접 확인.

### ③ 화면 캡처 — 대부분 WSL 창 캡처, 실제 윈도우 해상도 아님

이번 세션에서 보여드린 캡처는 전부 WSLg 가상 디스플레이(860×780 고정 창)에서
찍었다. 실제 윈도우 화면 배율(125%, 150% 등)이나 고해상도 모니터에서 글자가
잘리거나 창이 이상하게 나올 수 있다 — 특히 도움말 창은 이번에 **간격을
꽤 줄였다**(688px까지). 실제 화면에서 도움말을 열어 읽을 만한지 확인.

### ④ 스크래치패드 캡처 26장이 사라짐 — 이미 안내드렸지만 다시 적음

세션 중간에 서브에이전트 하나가 확인용 폴더를 통째로 비워서, 그 전까지
전달드렸던 캡처(`확인캡처/1_...` ~ `29_...`)가 전부 없어졌다. git 밖이라
복구 불가. 최종 화면 캡처는 다시 찍어서 이 세션 안에서 보여드렸지만, **세션
초반(설정 화면 링크, 조합 저장 등)의 옛 캡처는 없다.** 그 부분들이 지금도
맞게 동작하는지 궁금하시면 직접 한 번 켜서 훑어보시는 걸 권한다.

## 2. 코드에 남겨둔 것 (알고 있는 상태로 남긴 것)

이번 리뷰 과정에서 발견했지만, 병합을 막을 정도는 아니라고 판단해 그대로 둔 것.

### 압축 원본 삭제 줄의 위치·수정일이 빈칸

「압축 해제」를 켜고 원본 zip 을 지우는 옵션(`delete_original`)을 쓰면, 그
보류 줄에 위치·수정일 칸이 빈 채로 보인다(이유는 뜬다, 자리·날짜만 빔).
기능이 망가진 건 아니고 정보 하나가 안 보이는 것뿐이다.

**고치려면**: `organize/gui_model.py` 의 `preview()` 안 `if a.keeper is not None:`
조건을 `if a.kind == "quarantine":` 로 바꾸면 된다. 한 줄짜리 수정.

### 무리를 자르는 경계가 살짝 이상했던 것 — 이건 최종 리뷰에서 고쳤음

`_MAX_ROWS`(200줄) 를 넘는 아주 큰 폴더에서, 큰 무리 하나를 건너뛰고 그
뒤의 작은 무리가 몰래 끼어들 수 있던 버그. 최종 리뷰에서 잡아서 고쳤고
테스트로 못박아 뒀다 — **확인만 필요하고 할 일은 없음.**

## 3. 이번 세션에서 서브에이전트가 실수했던 것 (참고용)

작업 품질에 대한 감을 잡으시라고 남긴다 — 전부 리뷰 단계에서 잡혔고 지금
코드에는 남아 있지 않다.

| 무엇을 맡겼나 | 무슨 일이 있었나 | 어떻게 잡았나 |
|---|---|---|
| Task 1 (필드 하나 추가) | 테스트 하나가 **아무것도 검증하지 못함**(dedup 이 만들지 않는 케이스를 테스트해서 루프가 안 돎) | 리뷰어가 그 테스트를 "기능이 없던 예전 커밋"에 옮겨 돌려서 여전히 통과하는 걸로 확인 |
| Task 6 (파일 지우기 코드) | **손상된 실행 기록 하나로 사용자의 진짜 파일을 지울 수 있는 구멍 2개** | 가장 강한 모델로 검토 지시 → 실제 재현 스크립트로 찾음 |
| Task 8 (도움말 문구) | "헤드리스라 캡처 못 찍는다"며 계산으로 때움 → 실측과 105px 차이 | 컨트롤러(저)가 직접 다시 찍어서 거짓 보고임을 확인 |
| Task 5 (화면 그리기) | 확인용 스크래치패드 폴더를 통째로 삭제 (위 1-④) | 사후 발견, 복구 불가 |

**결론**: 개별 작업 결과를 그대로 믿지 않고 매번 리뷰·재검증하는 절차 덕분에
전부 병합 전에 잡혔다. 다만 이게 "AI 가 혼자 만들면 이런 일이 생긴다"는
근거이기도 해서, 위 1번(특히 ①②) 은 사람이 실제 환경에서 한 번은 눈으로
보는 걸 권한다.
